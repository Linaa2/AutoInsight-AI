# Critic Agent — Design Document

## 1. What is the Critic Agent?

The Critic Agent is an **adversarial review layer** in the pipeline. It takes
the insights generated by the Analyst Agent and systematically challenges them:
questioning assumptions, identifying weaknesses, suggesting alternative
explanations, and assigning a confidence level.

It does NOT replace or override the Analyst — it **enriches** the output by
adding a critical perspective that makes the final report more nuanced and
credible.

**Key position**: The Critic sits **between the Analyst and the Reporter**.
It does not block or modify the Analyst's insights — it adds a parallel
critique layer that the Reporter can integrate.

## 3. What the Critic Agent Produces

For each insight from the Analyst, the Critic outputs:

| Field           | Type   | Description                                        |
|-----------------|--------|----------------------------------------------------|
| `insight_title` | str    | Title of the insight being critiqued               |
| `strengths`     | str    | What is well-supported by the data                 |
| `weaknesses`    | str    | Logical gaps, unsupported assumptions, biases      |
| `alternatives`  | str    | Alternative hypotheses the Analyst may have missed |
| `confidence`    | str    | high / medium / low                                |
| `verdict`       | str    | supported / partially_supported / weak             |

**Example output:**

```json
{
  "insight_title": "Sales concentrated in Ile-de-France",
  "strengths": "Backed by data: 480/1500 orders (32%) from one region.",
  "weaknesses": "Does not account for population density. Ile-de-France has 19% of France's population, so 32% may not be as extreme as presented.",
  "alternatives": "The concentration could reflect the company's marketing spend or warehouse location rather than a real demand imbalance.",
  "confidence": "medium",
  "verdict": "partially_supported"
}
```

## 4. Three Evaluation Components — What's the Difference?

The project has three components that "evaluate" things. They are NOT the same:

### 4.1 LLM-as-Judge (Phase 7 — Evaluation)

| Aspect       | Detail                                                   |
|--------------|----------------------------------------------------------|
| **What**     | Scores the **quality of agent outputs** (1 to 5)        |
| **Input**    | Any agent output (profiler, analyst, reporter)           |
| **Output**   | Numeric score (1-5) + logged to LangFuse                |
| **Question** | "How good is this output?" (form, completeness, clarity) |
| **When**     | After the pipeline runs, as a quality check              |
| **Analogy**  | A **teacher grading an exam**                            |

### 4.2 Critic Agent (Phase 8 — Critique)

| Aspect       | Detail                                                       |
|--------------|--------------------------------------------------------------|
| **What**     | Reviews the **content and reasoning** of each insight        |
| **Input**    | Analyst insights + profile_data                              |
| **Output**   | Structured critique (strengths, weaknesses, alternatives)    |
| **Question** | "Is this insight logically sound? What did it miss?"         |
| **When**     | During the pipeline, between Analyst and Reporter            |
| **Analogy**  | A **peer reviewer challenging a research paper**             |

### 4.3 Uncertainty Estimator (Phase 8 — Uncertainty)

| Aspect       | Detail                                                       |
|--------------|--------------------------------------------------------------|
| **What**     | Computes a **confidence score** for each insight             |
| **Input**    | Insight + profile_data + critique                            |
| **Output**   | Confidence score (0-100%) + drivers (what affects the score) |
| **Question** | "How certain can we be about this insight?"                  |
| **When**     | After the Critic, uses critique as input                     |
| **Analogy**  | A **risk analyst assigning probability**                     |

### Summary Table

| Component              | Evaluates what?     | Output type        | Part of pipeline? |
|------------------------|---------------------|--------------------|-------------------|
| LLM-as-Judge           | Output quality      | Score (1-5)        | No (post-run)     |
| Critic Agent           | Reasoning quality   | Structured critique| Yes (in pipeline) |
| Uncertainty Estimator  | Data confidence     | Score (0-100%)     | Yes (in pipeline) |

**The Critic and Uncertainty Estimator work together:**
- Critic finds weaknesses → Uncertainty Estimator uses those weaknesses to lower
  the confidence score. An insight with many weaknesses gets a low confidence.

**The LLM-as-Judge is independent:**
- It runs after everything else to evaluate the overall quality of each agent's
  output. It doesn't feed back into the pipeline.

## 5. Why Have a Critic Agent?

### 5.1 For the product

Without the Critic, the system says: "Sales are concentrated in Ile-de-France."
The user has to trust it blindly.

With the Critic, the system says: "Sales are concentrated in Ile-de-France.
However, this region also has the highest population density, so the
concentration may be less extreme than it appears. Consider normalizing by
population before drawing conclusions."

**That's the difference between a toy demo and a credible analysis tool.**

### 5.2 For the presentation

The jury will likely ask: "How do you handle hallucinations?" or "How do you
know the insights are reliable?" The Critic Agent is a concrete, visible
answer to both questions.

### 5.3 For the architecture

It demonstrates **multi-agent collaboration** — agents that check each other's
work. This is a core concept in AI agent systems and shows architectural
maturity.

## 6. Implementation Plan

The Critic Agent follows the exact same pattern as `AnalystAgent` and
`ReporterAgent`:

```
agents/critic.py
├── CriticAgent (class)
│   ├── run(insights, profiler_output, profile_data) → dict
│   ├── _critique_single(insight, context) → dict
│   └── _parse_response(raw) → dict
├── critic_node(state) → dict   (LangGraph entry point)
└── CriticFormatter (class)
    └── to_markdown(critiques) → str

config/prompts.yaml
└── critic:
    ├── system: ...
    └── human: ...

tests/test_critic.py
```

**Inputs:** `insights` (from Analyst) + `profiler_output` + `profile_data`

**Outputs:** `critiques` (list[dict]) + `critic_output` (markdown)

**LLM used:** Text model (same as Analyst and Reporter)

## 7. Data Flow After Critic is Added

```
state["profiler_output"]  ──┐
state["profile_data"]     ──┤
state["sample_text"]      ──┘
                             │
                             ▼
                       AnalystAgent
                             │
                    state["insights"]
                    state["analyst_output"]
                             │
                             ▼
                       CriticAgent   ← also reads profiler_output + profile_data
                             │
                    state["critiques"]
                    state["critic_output"]
                             │
                             ▼
                      ReporterAgent  ← now receives insights + critiques
                             │
                    state["reporter_output"]
                             │
                             ▼
                       Enhanced Report
                    (insights + critique + confidence)
```

The Reporter prompt will be updated to include the critique, producing a
final report that says not just "here's what we found" but also "here's
how confident we are and what you should be cautious about."
